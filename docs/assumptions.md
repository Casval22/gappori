# 仮定と未確認事項

この実装は、利用者が提供した仕様書の比較モデルです。実機の公式仕様を確認したものではありません。

- 総16ポケット、通常15・特殊1、5球の非復元・等確率抽選を初期値とする。設定範囲は総6〜20、特殊0〜総数−1、通常列1〜8。段階は3球＋2球固定。
- 下駄3貫・舟5貫。同種複数要求を許す。費用は下駄5枚・舟10枚、数量上限30皿・単位1を仮の初期値とし変更可能。
- サンプル4型は表示確認用で、公式の型一覧ではない。8色は独自色。等数列も列番号で別のネタとして扱う。編集途中は順番固定、保存時に安定昇順ソートする。過去のスナップショットは再ソートしない。
- FC率は初期値null（不明）。不明の皿種だけFCを除外して警告する。明示的0と区別する。設定で全FCを除外できる。
- FCは行単位1回、または皿ごとの独立判定の「1回以上」。各行最大1個、行間・プレイヤー間で獲得独立と仮定。共通の物理抽選とは区別する。行を分けても正規化して統合する。
- FCは前半だけから列を決める。選んだ列の1貫補助／未充足全量、未出現列／未充足列の仮説を切替可能。後半の全可能性を積分し、その行の成立確率を最大化。同率は列番号順。グループ効用の最適FC選択ではない。
- FCは物理ポケットも球数も変更しない。全員への共通FC付与は範囲外。丸皿はFCなしとする。
- 丸皿は実機の要求1〜2貫・費用・今回の配当を登録したもののみ生成する。次ラウンドは再登録する。
- 配当は自動取得しない。実機で確認した総払出の手入力、未知、明示的デモを区別。数量指定を他数量へ外挿しない。0枚は既知として扱う。
- 型・ルール・要求・数量条件・ラウンドに配当を紐づける。過去の配当は「今回未確認」と表示し、再入力するまで使用しない。デモは下駄/丸皿2倍、舟12倍という架空値。明示操作でのみ有効になり、永続化・結果記録・実データへのインポートはできない。デモ開始時に状態を複製し、デモ中の設定・入力の編集も終了時に破棄する。
- 各人の予算は独立。残高を合算しない。数量削減や損失追跡の自動増額はない。
- 特殊抽選・JP・スタンプ・漁の報酬は計算対象外。実績の追加支出・獲得は手入力する。
- 持続性は現在の型・ルール・配当・BETを固定した独立ラウンドの反復。数量固定、必要費用を払えない人は停止。見送りは持続シミュレーションの対象外。
- 結果記録のBETベクトルは計算時のスナップショット。実機で変えた費用・払出は実績欄で入力する。実際の変更後ベクトルそのものの編集はv1に含めない。
- 残高・払出は非負整数、上限10億枚。型100件、配当500件、丸皿100件、履歴200件、バックアップ2MBを上限とする。到達時は自動削除せずエラーにし、バックアップ後の明示整理を促す。
- schemaVersion=1のみを受け付ける。旧/未来バージョンは移行仕様がないため、保護してインポートを拒否する。元JSONの退避を用意する。
- GitHub Pagesの同一オリジンでも公開baseごとに保存キーを分ける。URL変更時はJSONによる手動移行が必要。複数タブでの競合は保存停止と再読み込みで扱う。

実機の獲得率・費用・FC仕様・数量比例・配当のラウンド間継続性は未確認です。理論値、推定、デモ、手入力実績を混同しないでください。
